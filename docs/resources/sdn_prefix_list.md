# Resource: proxmox_sdn_prefix_list

Manages a Proxmox VE SDN prefix list. Prefix lists can be referenced by other SDN objects, e.g. as the `route_filter` of a fabric. Changes are staged in the pending SDN configuration and take effect when the SDN configuration is applied (see `proxmox_sdn_applier`).

## Example Usage

```terraform
resource "proxmox_sdn_prefix_list" "example" {
  id = "example"

  entries = [
    {
      seq    = 5
      action = "permit"
      prefix = "10.0.0.0/16"
      le     = 32
    },
    {
      seq    = 10
      action = "deny"
      prefix = "192.168.0.0/16"
      ge     = 24
      le     = 28
    },
  ]
}

# Prefix lists are staged in the pending SDN configuration until it is applied.
resource "proxmox_sdn_applier" "example" {
  lifecycle {
    replace_triggered_by = [
      proxmox_sdn_prefix_list.example,
    ]
  }

  depends_on = [
    proxmox_sdn_prefix_list.example,
  ]
}
```

### Optional

<a id="nestedatt--entries"></a>
### Nested Schema for `entries`

Required:

- `action` (String) The action of the entry. Must be `permit` or `deny`.
- `prefix` (String) The IPv4 or IPv6 prefix in CIDR notation.

Optional:

- `ge` (Number) Match prefixes with a length greater than or equal to this value.
- `le` (Number) Match prefixes with a length less than or equal to this value. Without `ge` or `le` an entry matches only the exact prefix and length.
- `seq` (Number) The sequence number of the entry.

## Import

Import is supported using the following syntax:

```shell
#!/usr/bin/env sh
# SDN prefix lists can be imported using their identifier, e.g.
terraform import proxmox_sdn_prefix_list.example example
```
